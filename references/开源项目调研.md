# 开源项目调研：全身 Live2D 自动化路线

调研日期：2026-11-01，遮挡专项复核：2026-11-02。源码结论对应当前落盘版本；项目快速变化时先核对 commit。

## 一句话选型

- **拆层主引擎：ComfyUI-See-through / 官方 see-through**。语义稳定，适合首版；最终精确度靠 1280-1536 推理、PSD 图层命名和人工质量门保证。
- **绑定和导出主引擎：PSD2Live**。唯一当前调研项目中能直接把分层 PSD 自动生成可编辑网格、变形器、物理，并导出 `.cmo3`、`.moc3`、`.model3.json` 与 `.vtube.json` 的开源工具链。
- **面捕快速原型：AutoLive2d**。适合 Web/Electron/OBS 预览和 MediaPipe 面捕，不作为 Cubism/VTS 最终导出器。
- **前沿参考：Bunraku**。结构化分层、网格与逐顶点位移的端到端思路最有价值；当前代码仓库没有可运行实现，不能作为生产依赖。

## 2026-11-02 遮挡专项增补

工程级版本表、命令和限制见 [项目核对](project-landscape.md)，可执行流程见 [遮挡工作流](occlusion-workflow.md)。关键修正如下：

- tk_seethrough 是独立 fork，不是当前上游 ComfyUI-See-through 的节点。它有真实的 `SeeThrough_GenerateLayers_Custom`、`auto_fill`、`Layer Filter` 和带 Original 的 Save PSD。
- AutoFill 只比较“层是否缺”和“可见 RGB 是否相似”，不是遮挡排序裁判。
- CObL 的真实论文是“Toward Zero-Shot Ordinal Layering without User Prompting”，训练域是多物体桌面场景。不能把同名机器人项目 `cobl_diffusion` 混进来，也不能宣称它已能裁判动漫衣领。
- RevealLayer 是遮挡感知的自然图像对象层分解，要求 bounding box，并使用 FLUX.1-dev；它不是 See-through 的语义替代品。
- Qwen-Image-Layered 支持可变 RGBA 层，但 BF16 权重约 53.74 GB；当前技能不把它列为 8 GB 默认方案。
- PSD2Live 的公开操作 `source_split_depth` 可以直接把上衣拆成前/后层并夹住脖子，比在 PSD 中手工复制更接近实际绑定结构。

## ComfyUI-See-through

### 能力和数据格式

- 输入：ComfyUI `IMAGE`；原始立绘可直接输入，不要求先抠图。
- 模型：LayerDiff3D 负责语义分层，Marigold 负责每个部件的深度。
- V3 原始输出为 **24 个语义层**：
  - 身体组 13 层：front hair、back hair、head、neck、neckwear、topwear、handwear、bottomwear、legwear、footwear、tail、wings、objects。
  - 头部组 11 层：headwear、face、irides、eyebrow、eyewhite、eyelash、eyewear、ears、earwear、nose、mouth。
- 后处理继续拆手、眼、耳、左右眼相关五官，并把头发聚类成前后发；同时给每层 `depth_median` 用于排序。
- `SavePSD` 节点实际落盘 RGBA PNG、深度 PNG 和 `layers.json`；ComfyUI 前端再据此生成可下载 PSD。
- 核心节点：`SeeThrough_LoadLayerDiffModel`、`SeeThrough_LoadDepthModel`、`SeeThrough_GenerateLayers`、`SeeThrough_GenerateDepth`、`SeeThrough_PostProcess`、`SeeThrough_SavePSD`、`SeeThrough_PartsToLayers`。

### 8 GB 显存结论

- 官方完整 bf16 在 1280 下约需 12-16 GB。
- 12 GB 可尝试 group offload，峰值约 10 GB。
- 8 GB 应选 NF4；模型文件合计约 5.3 GB：
  - LayerDiff NF4 约 3.51 GB。
  - Marigold NF4 约 1.80 GB。
- AutoLive2d 文档记录过一个可用的低显存命令：768 分辨率、15 步、NF4、CPU offload。
- 本机实测环境配置：Torch `2.9.1+cu128`、Transformers `4.49.0`、Diffusers `0.37.0`、bitsandbytes `0.50.2`。Transformers 5 会崩溃；该 Windows/8 GB 组合开启 group offload 也会崩溃。
- 关闭 group offload 后模型能加载并进入 30 步推理，但 50 分钟以上仍未结束，显存长期接近 7.8 GB。因此本机路线只能算“能跑”，不能算日常可用。
- 高精度正式拆层优先使用云端：Hugging Face 1280 或 ModelScope 1536。本机只在用户明确同意承担长时间运行、或隐私要求不允许上传时作为回退。

### 优点

- 输出类别与 Live2D 绑定直接对应，后续命名和绑定成本低。
- 有深度图和左右拆分，PSD2Live/AutoLive2d 都能直接消费。
- ComfyUI 节点化，可替换模型、缓存文本嵌入、导出 PSD。

### 缺点

- 基于人体语义类别，复杂叠穿服装、包、武器、交叠肢体、非 A/T 姿态容易合并或错分。
- 不会补全所有被遮挡区域；拆完后仍要检查前发下方脸、后发、手臂、裙裤和脚底。
- 本地 8 GB 完整 1280/30 步运行时间不可接受，不适合反复试错。

## PSD2Live

### 它真正做了什么

- 输入：RGB、8 位、透明背景的分层 PSD；也支持用 Layout JSON/zip 描述拆层结果。
- 自动识别中、英、日、韩图层名，生成：
  - Alpha 轮廓约束的自适应网格。
  - 头、身体、头发、衣服、四肢的 Warp/Rotation 变形器链。
  - 眼睛、眉毛、嘴、耳、视线、眨眼、呼吸、身体、头发物理等参数。
  - 待机、眨眼、点头、摇头等动作。
  - 可选自动骨架、FK/IK、头发与布料模拟。
- 网格关键实现：`AdaptiveMeshGenerator.kt` 从 Alpha 轮廓生成边缘环，支持洞、细桥、尖端、包裹拓扑和多种内部填充。
- 头部关键实现：`NinePoseFaceRig.kt`。这里的“九姿态”是 `ParamAngleX = {-45,0,45}` 与 `ParamAngleY = {-30,0,30}` 的 **3×3 姿态**，不是九个独立轴。面部采用经纬曲面、近远透视、眼睛单独收缩、虹膜补偿、嘴部嘴角滞后、远耳淡出，再叠加 `AngleZ` 倾斜。
- 头发还可用 `HeadTurn.kt` 的圆柱头壳模型做更细的深度转向；前后发使用不同半径、摆幅和上下点头权重。

### 导出机制

- `.cmo3`：`Cmo3Target.kt` 把中立 IR 转成 Cubism 可编辑层、纹理页、ArtMesh、Warp、Rotation、参数关键形、Glue、绘制顺序和摆锤物理；动作可另写 `.can3`。
- `.moc3`：`Moc3Target.kt` 输出 `.moc3`、`.model3.json`、纹理、`physics3.json`、动作、表情、姿势、命中区等 sidecar。
- VTube Studio：生成 `.moc3` 文件族和 `.vtube.json` 参数映射/热键。
- `.psd2live`：可继续编辑的源工程；不是只有最终二进制。
- 兼容 Cubism 3.0-5.3。每次导出会写损失报告；纹理精度可用 `Cmo3LayerArt` 在画布分辨率和原始分辨率之间选择。

### 自动化入口

- GUI/便携版：Windows x64 ZIP/EXE，自带 Java 运行时。
- CLI：`gradlew run --args="--input input.psd --output output-dir"`。
- 源码构建需要 JDK 21；若只用于生产，优先便携发行版，免装 JDK。
- MCP：应用启动后默认 `http://127.0.0.1:23871/mcp`，180+ 操作，可 `workspace_overview`、`workspace_inspect`、原子批量编辑和试运行。

### 优点

- 真正解决 PSD 到 Cubism/VTS 的最后一公里。
- 网格、头部九姿态、五官、物理、动作和损失报告都在同一工程内。
- CLI、MCP、可编辑工程完整，最适合作为当前 Skill 的全身绑定主路径。

### 缺点

- 自动生成只是初版；复杂衣服、长发、极角度转头、交叠四肢仍需人工或 MCP 精修。
- 全身自动骨架仍要逐项验收髋、膝、踝、手腕、裙摆和鞋底。
- 应用为 GPL-3.0；内部 IR/编译/运行时有 MIT 模块，但分发整合应用时遵守 GPL。

## AutoLive2d

### 能力和格式

- 输入：规范化分层 PSD。
- 导入：`ag-psd` 读取 PSD，语义命名分类，Alpha 裁剪，合并左右眼/手时用中心 Alpha 谷拆分。
- 网格：固定规则网格，不是 PSD2Live 的轮廓自适应拓扑；后发最多默认 14×8，前/侧发 11×8。
- 变形：每层关键帧、线性参数变形、伪 3D 头壳投影、眼睛裁剪、嘴缩放、头发与衣服尾端惯性。
- README 写“头部 9 轴”，但源码中头部角度仍是 `ParamAngleX/Y/Z` 三个参数；不要把该文案理解成九个独立旋转轴或 PSD2Live 的 3×3 九姿态拟合。
- 面捕：浏览器 MediaPipe FaceLandmarker，另可启用轻量 PoseLandmarker 驱动身体和手臂；带校准、平滑、防抖和分档。
- 输出：`project.json`、`adapter.json`、`template.json`、`runtime.html`、`reference.png`、各层 PNG、`manifest.json` 组成的成品 ZIP。
- **明确不是 Cubism/Inochi2D 模型导出器。**

### 可复用的 Cubism 辅助

仓库包含 5.4 alpha 外部 API 实验脚本，可创建 Part、Rotation/Warp Deformer、参数和参数关键槽，可改 ArtMesh 属性。可借鉴做“骨架和参数脚手架”，但当前 API 不能写 ArtMesh 顶点、UV、Warp 控制点，因此不能替代 PSD2Live 的几何烘焙。

### 优点

- Windows Web/Electron 体验完整，面捕和 OBS 预览方便。
- 可用于快速验证动作设计、镜头、表情和材质替换。
- 分层导入、伪 3D、眼口和头发惯性代码适合复用。

### 缺点

- 固定网格和线性变形对全身大幅动作、肩部、膝踝与厚层衣物的质量有限。
- 没有官方 Cubism `.cmo3/.moc3` 导出，不能作为最终 VTS 皮套交付。
- 自带 see-through 的本地低显存路线仍可能非常慢。

## Bunraku

### 官方描述的工作流

- Stage 1：把单张立绘直接生成一张**有序、已完成遮挡补绘的 RGBA 图层栈**。它不要求层片等于人体语义部件，包、发束、裙片都可各自成层。
- Stage 2：从每层 Alpha 建立三角网格，并在一个前向过程中预测每层每个顶点的二维位移，形成可拖动的参数关键姿态。
- 输出概念：完整图层栈 + 每层三角网格 + 参数驱动的逐顶点位移场。
- 项目页强调：一个冻结 checkpoint、不手工逐例调参、不 teacher forcing；示例帧都是原始模型输出。
- 输入分成 A-pose 站立图与动态立绘两组；A-pose 是训练分布中心。

### 基准设计

- 对比分解器时保持同一个冻结 Stage 2 checkpoint、同一组参数幅值和同一裁剪框，只替换 Stage 1 图层来源，从而把差异归因于分层质量。
- 该比较特别说明：语义分割拆层在静止时可能还可以，运动后才暴露衣物合并、道具粘连、长发/长裙被截断和肢体遮挡问题。
- 项目页还测试多参数同时驱动：四参数可以叠加；六参数时层次分离问题明显，说明预测位移场不能无限线性叠加。

### 优点

- 对复杂层片、任意道具和非标准服装的结构化表达能力优于固定的人体语义分类。
- 把“补全隐藏区域、网格、逐顶点变形”统一成一个可编辑资产，设计非常先进。
- 重绘 RGB 后可保持网格和动作不变，适合后续换装。

### 缺点和风险

- 当前 GitHub 仓库只有 README/引用，没有公开训练代码、推理代码或可下载 checkpoint。
- 数据集、权重和商用接入需要联系作者；代码与数据许可状态需要另行确认。
- 六参数叠加会拉散层片，极大幅全身动作没有证明可稳定用于生产。
- 现阶段只能作为架构参考和目标基准，不能部署到本机流水线。

## 兼容性与选型矩阵

| 项目 | 输入 | 输出 | 8 GB 本机 | 全身最终交付 | 建议角色 |
|---|---|---|---|---|---|
